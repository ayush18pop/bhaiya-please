# Screen build guide (internal, for the UI rewrite)

You are building production screens for **Bhaiya Please** in `apps/mobile` (Expo SDK 58, Expo Router, react-native-web, NativeWind v4, Reanimated 4, TanStack Query). One codebase runs on web and Android. The app talks only to `@bhaiya-please/core` through `useCore()`.

1. **Product spec**: `docs/UI_SCREENS.md` — every screen's purpose, contents, actions and states. Sections 2 (rules) and 3 (copy glossary) apply everywhere.
2. **Visual design**: `BhaiyaPlease-DesignSystem (1)/BhaiyaPlease-DesignSystem/` — `README.md`, `tokens/`, and the artboards in `canvas-source/*.dc.html` (inline-styled HTML: read the markup and styles literally — sizes, borders, colours, copy). 3. **UI kit**: `components/bp` (import from `@/components/bp`). Read every file in it once; it implements the design system. Do not restyle primitives inline — compose them.

## Rules

- **Never import** `react-native`'s `Text` for UI text; use `Text` from the kit (`variant`: display-xl, display, title, heading, body, label, caption, meter; `tone`). Icons: `Icon` from the kit with lucide icons.
- **Colours** only via tokens: `bg, fg, surface, raised, line, muted, edge` (theme-aware, Sunlight swaps them) and fixed `ink, paper, yellow, cng, go, mirchi`. Raw hex only inside SVG via `C` from `@/lib/utils`.
- **No blockchain words** in UI (wallet, transaction, gas, GLM, entity, Arkiv, on-chain, salt, geohash). See `docs/UI_SCREENS.md` §3. Only D5's Advanced section and Settings → Advanced may show IDs.
- **Every write** uses `SaveButton` (Saving / Saved / Couldn't save · Retry + plain reason; disabled offline). Never a bare spinner.
- **States**: every screen handles loading (`SkeletonCards` shaped like content), empty (`Empty` or a `Poster` for dead ends), error (`Alert`), expired-while-looking (`Alert tone="expired"` + next best action), offline (writes disabled — SaveButton does it).
- **Copy**: shared strings via `useT()` → `t('run.goLive')` (keys in `lib/i18n/en.json`, Hindi/Kannada provided). Feature copy: create `screens/<group>/copy.ts` with `defineCopy({ en: {...}, hi: {...} })` and read it with `useCopy(copy)`; interpolate with `fill(str, vars)`. Provide Hindi for the J1/J2 key screens using the `HI-*` artboards' text where available. Sentence case; capitals only on signage (plates, boards, stamps).
- **Motion** (design "Motion" board): use the kit (`Enter` for staggered blocks, `SlideInCard` for new list items, `useThump`/`Stamp animate` for stamps, `StatusRoad`, `PlateFlip`, `Meter` rolls digits, `Sink` press, `MelaLights marquee`). Long "signature moments" only where the spec says (receipt print-stamp-fly in B10, handoff stamp C8→C9, level-up flip D6/C10, barrier lift B8, gate strip). Respect reduced motion (kit does; for custom animations check `useReducedMotion()`).
- **Haptics** via `haptic` from `@/lib/haptics` (kit buttons already do).
- **Runner screens**: `Screen runner` (Sunlight-aware, roomier), primary actions `size="xl"` (64px), full width, bottom third.
- **Navigation**: expo-router `useRouter()`. Pushed screens use `Screen` with a back `TopBar`. Tab screens (Home / Activity / Profile) are rendered by `app/(app)/(tabs)/*` which import your `screens/...` default exports. Home screens render `HomeHeader` from `@/components/shell/HomeHeader` (society + bell + mode toggle) instead of a TopBar.
- **Accessibility**: 48px+ targets (56/64 runner), `accessibilityRole`/labels on custom controls, meaning never only in colour or decoration (stamps/crowds are aria-hidden).
- **Session**: `useSession()` → `{ mode, setMode, address, wallet, core, prefs, setPrefs, society, sandbox, guest, personas, ... }` (see `components/providers.tsx`). `guest` = read-only browse: any write must instead open a "Finish signing up to ask" sheet (`Sheet` + Get started → `/welcome/use`).
- **Time**: `useNow()` (`@/hooks/useNow`) for countdowns; it follows the sandbox clock.
- **Do not edit** files outside your ownership list below. The kit, shell, providers, hooks and lib are shared: if you truly need a change there, make the smallest additive change (new optional prop / new export), keep it backward compatible, and list it in your report. Never rename or remove exports.
